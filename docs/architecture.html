Adding an endpoint
// lib/api/fooApi.ts
import { api } from './index'

const fooApi = api.injectEndpoints({
  endpoints: builder => ({
    getFoos: builder.query<{ success: boolean; foos: Foo[] }, { workspaceId: string }>({
      query: ({ workspaceId }) => `api/foos?workspaceId=${workspaceId}`,
      providesTags: ['Foo'],
    }),
    createFoo: builder.mutation<{ success: boolean; foo: Foo }, CreateFooBody>({
      query: body => ({ url: 'api/foos', method: 'POST', body }),
      invalidatesTags: ['Foo'],
    }),
  }),
})

export const { useGetFoosQuery, useCreateFooMutation } = fooApi
RuleWhy
Add the tag to tagTypes in lib/api/index.tsTags are declared once on the base API; a module file cannot add its own.
Endpoint names are globalTwo modules injecting getTemplates throws at startup. Prefix: getWhatsAppTemplates, getSmsTemplates.
Import the file for side effects in lib/store.tsInjection only happens when the module is evaluated.
Always pass workspaceIdBackend requirePermission reads it from params/query/body/x-workspace-id; without it you get 400.
Use .id, never ._idEvery Mongoose model has a toJSON transform. No fallbacks like x._id || x.id.
Mutations must invalidatesTagsLists refresh through the cache, not manual refetch.
Persistence

lib/middleware/persistenceMiddleware.ts

After every action, serialises auth, workspace and theme to localStorage; loadPersistedState() hydrates preloadedState on boot so the dashboard renders before /api/auth/verify returns. Server truth still wins once verify completes.

Auth & Workspaces
httpOnly cookie session, verified on boot, workspace switching without reload
Login
POST /api/auth/login
→
auth-service sets auth_token cookie (httpOnly, SameSite=Lax, Secure in prod)
→
dispatch setUser + setCurrentWorkspace
→
router.push('/dashboard')
Boot / refresh
AuthInitializer mounts
→
GET /api/auth/verify
→
user + role.permissions + last active workspace
→
store hydrated, guards release
verify returns { user, role, workspace }. Permissions come from role.permissions (server-side role lookup for the active workspace), not from the user document. A 401 clears the store and redirects to /login.
Workspace switching (WorkspaceSwitcher)
StepDetail
1. PersistPOST /api/users/last-active-workspace so the next verify returns the same workspace.
2. Update storesetCurrentWorkspace(ws) and setUser({ ...user, workspaceId }).
3. Refresh dataEvery query keys on workspaceId, so RTK Query refetches automatically; no page reload.
4. PermissionsusePermissions re-queries roles for the new workspace; Sidebar items re-evaluate.

Role-based, resolved per workspace, enforced in UI and again on every backend route

BackendrequirePermission("x.y") on every route re-checks membership + role, so the UI gate is cosmetic, not security.
If a module disappears from the sidebar after refresh, check that /api/auth/verify returned role.permissions for the active workspace — that is the only source after boot.

Dev Workflow
Run the backend containers, point the frontend at the gateway, iterate with Turbopack
Start
# backend (crm-platform)
docker compose up -d            # 10 services + gateway :8000 + redis + n8n :5678

# frontend (CRM-SASS)
npm install
npm run dev                     # http://localhost:3000 (Turbopack, hot reload)
npx tsc --noEmit -p tsconfig.json   # type-check before committing
npm run build                   # production build (sitemap/feed need API_GATEWAY_URL reachable)

Anything without the NEXT_PUBLIC_ prefix is server-only and never shipped to the browser. Secrets for Mongo, Resend, OpenRouter, etc. belong to the backend's Infisical environment, not to this repo.
Rebuild rule

Changed backend code?

docker compose up -d --build <service>, then confirm the container was actually recreated (docker compose ps shows a fresh "Up"); use --force-recreate --no-deps <service> if it only rebuilt the image. The gateway resolves services dynamically, so it does not need a restart.

Conventions
House rules that reviews are strict about
RuleDetail
Theme tokens onlyUse bg-primary, text-muted-foreground, border-destructive/30, hsl(var(--primary)). Never hardcoded Tailwind colours like bg-blue-500; the app has light/dark themes.
No comments in codeNames carry the meaning. Explanations go in the PR description.
No defensive fallbacks for our own APIThe backend is ours: read x.id, data.items; do not chain || guesses. Only validate at real boundaries (user input, third-party responses).
Constants, not literalsShared values live in a constants file; env in .env; no inline magic strings/URLs.
FormsFormik + yup (older modules) or react-hook-form + zod (newer). Dialog/Sheet bodies get flex flex-col min-h-0 so long forms scroll instead of clipping.
Lists & cardsFixed-height rows for badges/actions so cards align regardless of content (see bot flow cards).
CommitsConventional prefix (feat:, fix:), no trailers. Never force-push; main is protected.
